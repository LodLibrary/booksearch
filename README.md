# חיפוש בקטלוג הספרייה (לוד)

אפליקציית Next.js מינימלית ב-RTL לחיפוש בקטלוג הספרייה העירונית לוד דרך שרת מקומי.

## הרצה מקומית

```bash
npm install
npm run dev
```

לאחר מכן לפתוח: `http://localhost:3000`

## איך האינטגרציה עם Agron עובדת

- ממשק המשתמש שולח בקשת `GET` לנתיב פנימי: `/api/search?q=...&column=...`.
- השרת (`app/api/search/route.ts`) מאמת קלט ושולח `POST` ל-Agron:
  - `column0` (0=כותר, 1=מחבר, 2=נושא)
  - `exprStr0`
  - `newSearch=1`
- הפענוח מתבצע בצד שרת בלבד עם `cheerio` (`lib/agron.ts`), ומוחזר JSON נקי.
- אם אין תוצאות, נעשה ניסיון fallback:
  1. `GET` לעמוד החיפוש.
  2. חילוץ טוקן Joomla (input hidden עם value=1 ושם hash-like).
  3. `POST` נוסף עם הטוקן.

## Autocomplete

נוסף endpoint בסיסי: `/api/suggest`.
כרגע הוא מחזיר מערך ריק, עם TODO ברור לחיבור endpoint אמיתי אם יימצא ב-JS הישן (`checkKeyPress()`).

## מה לשנות אם מבנה ה-HTML ב-Agron משתנה

- לעדכן את הסלקטורים בפונקציה `parseResultCards` בקובץ `lib/agron.ts`.
- לעדכן היגיון חילוץ של `title`, `author`, `year`, `shelfMark`, `classification` בהתאם למבנה החדש.
- מומלץ לשמור לוגים (server-side) לדוגמאות HTML חדשות לצורך התאמה.

## מגבלות גישת Scraping לעומת API רשמי

- תלוי לחלוטין במבנה HTML שעלול להשתנות ללא התראה.
- אין חוזה נתונים יציב (schema) כמו ב-API רשמי.
- סיכוי גבוה לשבירה/תוצאות חלקיות במקרה של שינויי UI או מנגנוני אבטחה.
- לכן קיימים fallback והודעות שגיאה ידידותיות, אבל עדיין זה פתרון פחות יציב מ-API.

## פריסה ל-Vercel

כן — האפליקציה מתאימה לפריסה ב-Vercel.

- נתיבי ה-API מוגדרים לרוץ ב-`nodejs` (לא Edge) כדי לתמוך ב-`cheerio` וב-scraping יציב.
- החיפוש תמיד מתבצע דרך `/api/search`, כך שאין פנייה ישירה ל-Agron מהדפדפן.
- מומלץ להגדיר ב-Vercel:
  - Region קרוב לישראל/אירופה לצמצום latency מול אתר הספרייה.
  - Monitoring ללוגים של `/api/search` כדי לזהות שינויי HTML או חסימות.

מגבלות חשובות בפרודקשן:
- אם אתר המקור חוסם תעבורה משרתי ענן או משנה markup, ייתכנו תקלות חיפוש עד התאמת הסלקטורים.
- אין API רשמי, ולכן היציבות תלויה במבנה HTML של האתר החיצוני.
